# 定时自动更新机制

## 目标

- 将采集频率从原来的每日一次缩短为每 12 小时一次。
- 自动采集、候选发现、口碑信号都沿用同一套来源分组和质量门槛。
- 线上定时任务只在真实采集数据变化时提交更新，减少无意义发布。

## 机制

1. GitHub Actions 每 12 小时运行一次 `collection:scheduled`。
2. 采集脚本先刷新真实来源报告，再生成 `liveActivities.generated.ts`。
3. 只有“可直接自动采集”的高质量来源可以进入公开精选。
4. “半自动候选”进入候选池思路，不直接污染公开推荐。
5. “只做口碑信号”只参与判断辅助，不自动生成活动。
6. 更新后先跑测试和构建，全部通过才提交采集结果。
7. 如果仓库已连接 Vercel，提交后由 Vercel 自动发布最新页面。

## 时效与质量平衡

- 高频但不过载：12 小时足够覆盖白天和晚间新增信息，不把来源网站推到过高访问压力。
- 质量优先：公开页面只展示可确认来源；噪声较大的来源先进入候选或口碑层。
- 可追溯：每次采集报告保存在 `docs/superpowers/reports/`，方便回看哪类来源稳定、哪类来源需要降级。
