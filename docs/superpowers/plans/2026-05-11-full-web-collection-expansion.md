# 全网活动采集扩展计划

目标：把“深圳学习 Hub”的活动来源从少量列表页，扩展为覆盖官方渠道、活动平台、内容社区、搜索发现和用户线索的多层采集体系。核心不是把所有信息都放上来，而是尽量发现全、核对准、解释清楚。

## 1. 来源分层

### A. 确认源
用于确认活动是否真实存在，优先级最高。

- 主办方官网、场馆官网、大学/书店/科技馆/展馆官网
- 政府、协会、园区、公共文化机构公告
- 活动报名页、展会官网、会议官网

使用方式：可以直接进入活动详情和推荐判断。没有确认源的活动，不进入高把握推荐。

### B. 发现源
用于扩大覆盖面，帮助发现活动线索。

- 活动行、豆瓣同城、Eventbrite、Meetup、Luma 等活动平台
- 深圳站、学习、科技、创业、亲子、读书、展会等分类页
- 搜索引擎结果、站内搜索、RSS、站点地图

使用方式：发现候选活动后，继续寻找确认源。只靠发现源可以进入“待补充”，不能直接进入精选。

### C. 舆论源
用于判断热度、口碑、适配度和风险，不直接证明活动可靠。

- 公众号文章
- 小红书笔记
- 豆瓣小组/同城讨论
- B 站、视频号、抖音等公开内容
- 社群转发、媒体报道

使用方式：只作为“公开反馈”和“风险提示”的证据。热度高不能直接加成活动价值，负面反馈可以触发复核。

### D. 用户线索
用于补足机器采集不到的小活动。

- 用户提交
- 主办方提交
- 用户纠错
- 志愿编辑补充

使用方式：进入待补充队列，由系统先查重、补来源、评估，再决定是否展示。

## 2. 采集覆盖矩阵

第一阶段优先覆盖这些组合：

- 类别：电子展会、游戏展会、科技展会、技术大会、社科讲座、读书沙龙、Hackathon、亲子科技
- 区域：南山、福田、宝安、龙岗、罗湖、盐田、光明
- 时间：未来 14 天优先，未来 30 天补充观察
- 人群：亲子、成人、亲子和成人都适合
- 来源：确认源、发现源、舆论源、用户线索都要计数

后台必须显示覆盖缺口，例如：

- 本周亲子科技活动是否只来自一个来源
- 福田/宝安是否长期缺少数据
- 读书沙龙是否只有活动平台，没有书店官网确认
- 某类活动是否长期没有公开反馈

## 3. 标准采集流程

1. 发现线索：从来源池、搜索词、平台列表、用户提交里抓到活动标题、链接和摘要。
2. 结构化：抽取时间、地点、主办方、价格、报名方式、人群、年龄段、注意事项。
3. 查重合并：按链接、标题、时间、地点、主办方做合并，保留所有来源证据。
4. 找确认源：优先寻找主办方或场馆页面；找不到则降低把握度。
5. 补舆论信号：读取公开反馈摘要，判断是否有“排队混乱、商业推销、临时取消、体验差”等风险。
6. 评估：分别计算活动价值、来源可靠性、主办方记录、场地匹配、公开反馈、风险提示。
7. 分流：
   - 信息完整且看点明确：进入精选候选
   - 来源不足但可能有价值：进入待补充
   - 风险高或信息冲突：进入复核
   - 重复、过期、取消：归档

## 4. 采集适配器拆解

### T1 来源目录升级

为每个来源增加：

- sourceFamily：确认源 / 发现源 / 舆论源 / 用户线索
- accessMode：公开网页 / API / RSS / 搜索 / 授权导入 / 人工提交
- coverageTags：类别、区域、人群
- complianceLevel：可自动抓取 / 需授权 / 仅人工引用 / 不采集
- confirmationPower：能否作为活动真实性确认依据

### T2 官方和场馆适配器

优先做稳定来源：

- 深圳科技馆、博物馆、图书馆、书城、大学、园区、展馆
- 展会官网和会议官网
- 政府/协会/公共文化机构公告页

目标：拿到高把握活动，减少对平台推荐流的依赖。

### T3 活动平台适配器

优先做公开列表页和详情页：

- 活动行深圳站及学习/科技/创业/亲子分类
- 豆瓣同城深圳
- Eventbrite 深圳
- Meetup / Luma 的深圳关键词结果

目标：扩大候选池，但必须继续找确认源或补充证据。

### T4 搜索发现适配器

维护一组查询模板：

- 深圳 + 本周 + 科技展 / 电子展 / 游戏展
- 深圳 + 亲子 + 科技 / AI / 创客
- 深圳 + Hackathon / Meetup / 读书会 / 社科讲座
- 南山/福田/宝安 + 活动 + 报名

目标：发现没有进入平台的大量长尾活动。

### T5 内容社区和社媒信号

公众号、小红书、豆瓣讨论等不作为第一确认源，而是做三件事：

- 发现活动线索
- 补充参加者反馈
- 识别风险和适配度

对于需要登录、授权或平台限制明显的内容，不做绕过式采集，只做授权导入、人工链接提交或合规第三方数据接入。

### T6 查重与合并

同一个活动可能同时出现在官网、活动行、公众号、小红书和社群转发里。合并规则：

- 强匹配：同一官方链接或同一报名链接
- 中匹配：标题相似 + 时间相同 + 场地相同
- 弱匹配：标题相似 + 主办方相同，但时间地点不完整

合并后保留所有证据，不覆盖来源。

### T7 采集质量压测

每周自动生成报告：

- 每个来源成功率
- 每个来源平均活动数
- 重复率
- 可结构化字段完整度
- 需要复核比例
- 最终进入精选比例

这份报告用于调权重，而不是靠主观感觉判断来源好坏。

## 5. 第一轮落地顺序

1. 扩展来源模型，区分确认源、发现源、舆论源。
2. 增加活动行深圳站、深圳官方/场馆类来源、搜索发现源。
3. 建立查重合并层，避免全网采集后重复膨胀。
4. 把公众号和小红书先接为“线索/反馈源”，不直接进入精选。
5. 在后台增加覆盖缺口：按类别、区域、人群、来源类型看本周采集是否偏窄。
6. 每周跑采集质量报告，再根据真实数据校准来源权重。

## 6. 不能踩的坑

- 不能把热度当价值。小红书或公众号讨论多，只能说明需要看，不等于值得去。
- 不能把官方当高价值。官方来源提高可信度，但活动本身仍要看内容、组织和场地。
- 不能把平台列表当全网。活动行、豆瓣、Eventbrite 只能覆盖一部分，长尾活动需要搜索和用户线索。
- 不能绕过登录或平台限制采集。需要授权的来源，要么走授权导入，要么作为人工线索。
- 不能只追求数量。最终指标是“发现全 + 重复少 + 可解释 + 低误推”。
